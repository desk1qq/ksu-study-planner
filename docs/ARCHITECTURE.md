# Архитектура проекта

Проект работает непосредственно в браузере и не требует сборки. Все сценарии подключаются как обычные JavaScript-файлы с атрибутом `defer`.

## Порядок загрузки

1. `scripts/core/planner.js` - независимые функции дат, списков и распределения задач.
2. `scripts/app.js` - состояние приложения, хранение данных, форма создания и общий рендер.
3. `scripts/features/note-tools.js` - оформление карточек и напоминания.
4. `scripts/features/notes.js` - представления, редактор, архив и корзина.
5. `scripts/ui.js` - поиск, тема, вид карточек и боковая панель.
6. `scripts/features/profile.js` - локальный профиль.
7. `scripts/bootstrap.js` - восстановление состояния и единственный первоначальный рендер.

Такой порядок отделяет объявления от запуска и исключает повторную отрисовку при загрузке.

## Поток данных

```text
Форма → проверка и разбор ввода → savedPlans → localStorage
                                      ↓
                               renderPlan()
                                      ↓
                    карточки / архив / корзина / поиск
```

Основные данные хранятся под ключом `exam-planner-v1`. Тема, выбранный раздел, состояние боковой панели и профиль используют отдельные ключи, поэтому изменение одной настройки не требует перезаписывать все учебные задачи.

## Границы модулей

- `core` не обращается к DOM и содержит переиспользуемую вычислительную логику;
- `app.js` владеет массивом `savedPlans` и функцией `persist()`;
- файлы в `features` отвечают за отдельные пользовательские сценарии;
- `ui.js` управляет только глобальными элементами интерфейса;
- `bootstrap.js` не содержит бизнес-логики и служит явной точкой запуска.

При добавлении функции вычисления её следует помещать в `core`. Новый самостоятельный сценарий интерфейса следует оформлять отдельным файлом в `features` и подключать перед `bootstrap.js`.
